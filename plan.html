ACC 検知回路（Codex 推奨）:
ACC 12V → 1kΩ抵抗 + TVSダイオード → フォトカプラ（PC817）LED → GND
フォトカプラ出力: 3.3V → 4.7kΩプルアップ → GPIO
抵抗分圧のみは禁止。車載サージ（最大80V超）でGPIO破壊の危険あり。
動作仕様:
① ACC ON 検知 → 1〜3秒待機（起動ノイズ除去）
② 全センサースキャン（GPIO HIGH = 開放 = 異常）
③ 異常あり → LED 点滅 + ntfy.sh 送信
④ 走行中は 5秒間隔で再チェック。同一異常の ntfy 再送は 10分間隔で抑制
⑤ センサー線断線もHighになるためフェイルセーフ設計（誤判定注意。デバウンス 300ms 確定）
配線注意: センサー線をインバーター・DC-DC・モーター配線に近接させない。ルーフ等長距離配線はコルゲートチューブ保護 + 防水コネクタ（IP67以上）必須。シールド片端接地。

窓開閉 独立警告システム（RPi非依存・リレー回路）

RV窓（サイド・リア・バック）の開閉チェックはRPiに依存させず、リレー1個だけのシンプルな回路で完結させる。ACC ON中のみ動作し、いずれかの窓が開いていれば警告ランプ点灯。

部品仕様備考
リレー12V自動車用 SPDT（NC接点付き）数百円で入手可
フライバックダイオード1N4007等コイル逆起電力保護。コイルに並列
警告ランプLED＋抵抗 or パイロットランプブザー追加時は同じNC接点に並列接続
窓センサー磁気リードスイッチ 常閉(NC) × 3サイド・リア・バック。直列（ループ状）に配線
ヒューズ1A程度ACC分岐部
配線構成:
ACC 12V+ → ヒューズ → 窓①(直列) → 窓②(直列) → 窓③(直列) → リレーコイル(+) → リレーコイル(-) → GND（コイルに並列でフライバックダイオード）
ACC 12V+ → リレーNC接点(COM側) → 警告ランプ(+) → ランプ(-) → GND
動作原理:
① 窓が全部閉：3つのリードスイッチが直列で全て導通 → リレーコイル励磁 → NC接点「開」→ ランプ消灯
② いずれか1つでも開：ループが切れる → リレー非励磁 → NC接点「閉」→ ランプ点灯
③ センサー線の断線も回路が切れるため開扱いになりランプ点灯（フェイルセーフ）
④ ACC電源が入っているときだけ動作（ACC OFF中は無通電）
配線注意: リードスイッチは直列（ループ状）で配線（並列にすると「全部開いたときだけ検知」の逆挙動になる）。窓枠側の接続部は防水コネクタ（IP67以上）必須。信号線はインバーター・DC-DC・モーター配線から離し、GND線と軽くツイストしてノイズ対策。
拡張時（スライドドア等）は同じループに直列でスイッチを追加するだけで回路変更不要。

LED 照明制御（Phase 4）

① 車内メインライト — PWM 調光サイクル・タッチ3箇所

タッチごとに状態が1段階進む: 切 → 弱（30%）→ 強（100%）→ 弱（30%）→ 切
3箇所（スライドドア/ベッド横①/ベッド横②）どこからタッチしても同じ state 変数を1段階進める（ソフト側で3 GPIOの立ち上がりエッジを OR 判定）。
スマホ（Flask / MQTT）からも同じ state 変数を操作して連携。
LED本体: DC24V/5A（120W）COBテープ、実機スペック確認済み。天井幹線(25A/2sq)からサブヒューズブロック経由で7.5Aヒューズ・0.5sqケーブルで分岐。

LED24V 対応テープ / パネルヒューズボックスから直給電。RPi はドライバーモジュールでスイッチのみ
タッチセンサー設置の注意: TTP223は自己容量式のため、木材パネル越しの検出は厚み3〜5mm程度が実用限界（ガラス/アクリルでも同程度）。羽目板が10mm程度ある場合はセンサー設置箇所だけ3〜5mmまで薄く削って埋め込む。

② スライドドア足元ライト — 人感自動点灯

モジュール型番設定・接続
人感センサー（PIR）AM3123.3V 直接駆動可。検知距離 3m / 検知角 100°。出力 → GPIO 入力

③ 室内換気扇（天井、1台） — PWM風量制御

物理スイッチなし、Pico不使用。RPi5 GPIO13から直接ファンのPWM線を駆動するシンプル構成（MOSFET・ゲート抵抗・プルダウン抵抗は不使用）。
モジュール型番設定・接続
換気扇Walfront DC24V 4pinPWMブロワー黒GND/赤VCC/黄Tach/青PWM。実機スペック確認済み（24V・0.75A・18W）
主電源(赤/黒)—サブヒューズブロック(0.3sq/2Aヒューズ)から常時通電で直結
PWM(青)—GPIO13(ハードウェアPWM)に直結（保護抵抗も省略）。デューティ比で切/弱/中/強を制御
Tach(黄)—未使用。絶縁して放置
「切」はPWM=0%指令のみに依存（MOSFETによる主回路遮断は行わない）。個体差で微弱回転が残る可能性があるため実機で要確認。

④ バッテリ庫換気扇（Walfront、2台目） — MPPT BLE温度連動PWM制御

室内換気扇と同一機種・同一パターン（MOSFET不使用、GPIO直結）。制御ロジックのみ異なり、RPiがMPPT(Renogy Rover)のBLEバッテリー温度データを読み取って自動制御する。
モジュール型番設定・接続
換気扇Walfront DC24V 4pinPWMブロワー（室内用と同一機種）黒GND/赤VCC/黄Tach/青PWM
主電源(赤/黒)—バッテリ庫用サブヒューズ(0.3sq/2Aヒューズ)から常時通電で直結
PWM(青)—GPIO18(ハードウェアPWM)に直結
Tach(黄)—未使用。絶縁して放置
温度データ取得Renogy BT-1 → BLEcyrils/renogy-bt等のPythonライブラリでバッテリー温度を定期取得（例: 30秒毎）。閾値超えでGPIO18のPWMデューティを上げる、ヒステリシスを設けて頻繁なON/OFFを防止
RPi非依存のフェイルセーフ（バイメタルサーモスタット直結案）は不採用。RPiがフリーズ・停止すると換気も止まるリスクをユーザーが許容した上での設計。
