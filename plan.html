現況と今後の予定（2026-09-20時点）

稼働中・実装済み

項目状態・内容
監視・操作ダッシュボード自作（collector + Flask server）。BMS・Rover・Orion をBLEで30秒周期に取得し、スマホから閲覧。BMS充放電スイッチ、MPPT ON/OFF、ファン・ライト操作に対応
SOC基準の90%/20%運用BMSのSOC 90%以上でRoverのソーラー充電を自動停止、80%未満で再開（ブースト/フロート電圧はRoverに任せる）。SOC 30%以下でPushover警告。実装・稼働中だが、充電器が電圧判断でSOC80%前後でフロートに入るため、90%到達での停止はまだ発動していない。Pushoverはトークン未設定で未配信
記録エンジン稼働時間（Orionの充電状態から検知）、本日の電力収支（充電/放電Wh）、OBD2走行距離（給油記録）
照明・換気メインLED調光（タッチ×3、切/30/60/100%、切り替えは3秒フェード）、室内換気扇（タッチ×1、切/30/60/100%）。クーラー稼働中にタッチ入力の誤検知が多発した（2026-09-21、1日2,227件）ため、0.3秒以上触れ続けたときだけタッチとみなす処理（2026-09-21）、短時間に4回以上入ったらノイズとみなして直前の光量に戻し一時的に無効化する処理、画面の「タッチ操作 有効/無効」スイッチを追加。原因（電気ノイズ・振動・電源）は特定中。バッテリ庫ファンはGPIO18出力のみで、温度連動の制御ロジックは未実装
固着・停止への備えデータ収集の1周を300秒で打ち切り、systemdウォッチドッグ（collector 420秒 / server 120秒）、データが古いとき画面に赤警告。Pi本体のハードウェアウォッチドッグはOS標準で有効（フリーズ時の再起動の実試験は未実施）

#項目待ち条件・次の一手
1Orion（走行充電器）のVE.Direct対応純正USBケーブルを購入済み、到着待ち（2026-09-27以降）。USBで読み取り → デバイスモード書き込みの実機検証 → SOC自動制御へ組み込み → 過熱の調査 → 「一時的な90%充電モード」（エアコン長時間使用向け）の設計
2エアコンIR制御モジュール到着済み、配線待ち。ピンは下の構成図・ピン割り当て表（案）。配線後に起動設定へgpio-irのoverlay追記＋Pi再起動 → リモコン信号の学習
3車内温度センサー（SCD40）購入済み・未配線。I2C配線 → 読み取り → ヘッダー表示 → 室内ファンの自動制御
4Pushover通知アカウント作成とAPIトークンの設定（低SOC警告・BMS操作失敗・空気質異常の通知が実際に届くようになる）
5インバーター（MWXNE 24V 2000W）の制御・状態取得有線リモコン（RCU）の通信の解析と、無線リモコン信号の受信機（購入済み・到着待ち）。ON/OFF・出力Wの取得が狙い
6信頼性の底上げPi 5のRTC電池、USB電源ケーブルの抜け止め。Bluetooth単体の固着への段階的な復旧（サービス再起動 → 電源入れ直し → Pi再起動）は、実際に不調が出てから対応
7OBD2の残り水温・外気温・電圧・速度の常時取得への統合の判断、給油後の平均燃費・走行可能距離の計算
8検証待ち（運用しながら観察）SOC 90%停止の発動条件、BMSのSOC自動校正が働いているか、停止解除後のRoverのバルク再開

ACC 連動走行前チェックシステム（Phase 4）

ACC 電源 ON を検知し、走行前に収納忘れ・開けっぱなしを自動チェック。
窓開閉（5箇所）・ソーラーパネル展開（2箇所）・RVジャッキ展開（4箇所）の3系統は、いずれもRPi非依存の独立リレー回路に分離 → 下記「走行前チェック 独立警告システム」参照（2026-09-05、3系統ともRPi GPIO監視からリレー方式に統一）
RPi側でGPIO監視するのは「他4」項目（サイドオーニング・外部電源ケーブル・給排水ホース・スライドドア・ルーフベンチレーター等）のみ。
Codex (gpt-5.5) レビュー反映: ACC 検知はフォトカプラ絶縁必須。デバウンス・抑制込みの設計。

ACC 検知回路（Codex 推奨）:
ACC 12V → 1kΩ抵抗 + TVSダイオード → フォトカプラ（PC817）LED → GND
フォトカプラ出力: 3.3V → 4.7kΩプルアップ → GPIO
抵抗分圧のみは禁止。車載サージ（最大80V超）でGPIO破壊の危険あり。
動作仕様:
① ACC ON 検知 → 1〜3秒待機（起動ノイズ除去）
② 全センサースキャン（GPIO HIGH = 開放 = 異常）
③ 異常あり → LED 点滅 + ntfy.sh 送信
④ 走行中は 5秒間隔で再チェック。同一異常の ntfy 再送は 10分間隔で抑制
⑤ センサー線断線もHighになるためフェイルセーフ設計（誤判定注意。デバウンス 300ms 確定）
配線注意: センサー線をインバーター・DC-DC・モーター配線に近接させない。ルーフ等長距離配線はコルゲートチューブ保護 + 防水コネクタ（IP67以上）必須。シールド片端接地。

走行前チェック 独立警告システム（RPi非依存・リレー回路 ×3系統）

窓開閉・ソーラーパネル展開・RVジャッキ展開の3系統はRPiに依存させず、系統ごとにリレー1個のシンプルな回路で完結させる（2026-09-05、3系統に統一）。ACC ON中のみ動作し、系統内のいずれかのセンサーが異常位置なら、その系統の警告灯が点灯。系統ごとに独立した警告灯3個を設置し、どこが異常かひと目で分かるようにする。

系統リードスイッチ数警告灯備考

ソーラーパネル開閉2箇所LED(青)チルト+スライド
RVジャッキ開閉4箇所LED(黄)前後左右
部品（系統ごとに必要な数）仕様備考
リレー12V自動車用 SPDT（NC接点付き）× 1Heschen JD1914等、5ピン・インターロックソケット付き。3系統で計3個
フライバックダイオード1N4007等 × 1コイル逆起電力保護。コイルに並列。3系統で計3個

磁気リードスイッチ常閉(NC) × 系統内の箇所数系統内で直列（ループ状）に配線。合計11個（窓5+ソーラー2+ジャッキ4）
ヒューズ1A程度 × 1ACC分岐部、系統ごとに独立。3系統で計3個
配線構成（系統ごとに同一パターン）:
ACC 12V+ → ヒューズ → センサー①(直列) → センサー②(直列) → …→ リレーコイル(+) → リレーコイル(-) → GND（コイルに並列でフライバックダイオード）
ACC 12V+ → リレーNC接点(COM側) → 警告灯(+) → 警告灯(-) → GND
動作原理:
① 系統内のセンサーが全て正常位置（閉/格納）：直列で全て導通 → リレーコイル励磁 → NC接点「開」→ 警告灯消灯
② いずれか1つでも異常位置（開/展開）：ループが切れる → リレー非励磁 → NC接点「閉」→ 警告灯点灯
③ センサー線の断線も回路が切れるため異常扱いになり警告灯点灯（フェイルセーフ）
④ ACC電源が入っているときだけ動作（ACC OFF中は無通電）
配線注意: リードスイッチは系統内で直列（ループ状）で配線（並列にすると「全部異常のときだけ検知」の逆挙動になる）。可動部との接続部は防水コネクタ（IP67以上）必須。信号線はインバーター・DC-DC・モーター配線から離し、GND線と軽くツイストしてノイズ対策。
拡張時は該当系統のループに直列でスイッチを追加するだけで回路変更不要。
